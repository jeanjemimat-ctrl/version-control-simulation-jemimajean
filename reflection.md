During this Version Control project, I practiced using Git and GitHub to manage changes to a project using branches, commits, and merges. I started by creating a feature branch for the header and made the required changes to index.html. I then staged and committed my changes before switching back to the main branch. I created another feature branch for the footer and followed the same process. I have worked alongside developers for years, but this helped me understand why they use branches to work on different parts of a project without making changes directly to the main branch. This is now making sense to me.

The most challenging part for me was creating and resolving a merge conflict. After merging the footer branch into main, I attempted to merge the header branch, and Git showed that there was a conflict in index.html. I used the VS Code Merge Editor to look at the current and incoming changes and choose which version I wanted to keep. After resolving the conflict, I completed the merge and used git status to make sure everything was clean.

The pull request process also helped me understand how GitHub can be used for collaboration. A pull request gives other developers a chance to review changes before they are merged into the main branch. This allows the team to catch issues, provide feedback, and make sure the changes are ready. Overall, this project gave me a better understanding of how branches, commits, merges, conflict resolution, and pull requests work together in a real development environment. Yes, we can do everything manually, but it was enlightening to use commands and code to shape and build an environment.
